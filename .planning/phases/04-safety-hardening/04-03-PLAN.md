### Task 2 — Migrate event buffer from `threading.local` to `ContextVar`

**File:** `django_inspector/storage/flush.py`

Replace the thread-local pattern with:

```python
from contextvars import ContextVar

_buffer_var: ContextVar[list | None] = ContextVar("inspector_event_buffer", default=None)


def _get_buffer() -> list:
    buf = _buffer_var.get()
    if buf is None:
        buf = []
        _buffer_var.set(buf)
    return buf
```

Remove the `import threading` and `_local = threading.local()` lines.

All other functions (`buffer_event`, `flush_events`, `clear_buffer`) remain unchanged because they call `_get_buffer()` to get the list and operate on it in-place — the list identity is stable for the lifetime of a request context.

**Acceptance:**
- `buffer_event(...)` / `flush_events()` / `clear_buffer()` behave identically to before in synchronous (WSGI) tests.
- Async isolation test: two tasks running concurrently do not share each other's buffered events (see Task 5).

### Task 7 — Concurrency regression tests (ASYNC-01, ASYNC-02)

**File:** `tests/test_async_isolation.py`

Two tests required:

**Test A: Event buffer isolation:**
```python
import asyncio
import pytest
from django_inspector.storage.flush import buffer_event, _get_buffer, clear_buffer
from django_inspector.tracing.context import set_trace_id, generate_trace_id, clear_trace_id

@pytest.mark.asyncio
async def test_event_buffer_isolation():
    """Two concurrent async tasks must not share event buffers."""
    results = {}

    async def task(name, path):
        tid = generate_trace_id()
        token = set_trace_id(tid)
        buffer_event(tid, "test.event", {"path": path})
        await asyncio.sleep(0)  # yield
        results[name] = [e["metadata"]["path"] for e in _get_buffer()]
        clear_buffer()
        clear_trace_id(token)

    await asyncio.gather(task("a", "/a"), task("b", "/b"))
    assert results["a"] == ["/a"], f"Task a got unexpected events: {results['a']}"
    assert results["b"] == ["/b"], f"Task b got unexpected events: {results['b']}"
```

**Test B: SQL query log isolation:**
```python
from django_inspector.watchers.sql import _get_query_log, clear_query_log

@pytest.mark.asyncio
async def test_sql_query_log_isolation():
    results = {}

    async def task(name, query):
        _get_query_log().append({"sql": query})
        await asyncio.sleep(0)
        results[name] = [e["sql"] for e in _get_query_log()]
        clear_query_log()

    await asyncio.gather(task("a", "SELECT 1"), task("b", "SELECT 2"))
    assert results["a"] == ["SELECT 1"]
    assert results["b"] == ["SELECT 2"]
```

**Dependency note:** `pytest-asyncio` must be in dev dependencies. Check `pyproject.toml`; if absent, add it.

**Acceptance:**
- Both tests pass.
- WSGI equivalents in `test_request_watcher.py` and `test_exception_watcher.py` continue to pass.

## Risks

- `ContextVar` default is `None`; `_get_buffer()` must handle the first-access case (creates a new list, sets it). If `_buffer_var.set(buf)` is called from a concurrent context that hasn't set a value yet, each coroutine correctly gets its own list because `asyncio.create_task` copies the current context.
- `asyncio.gather` shares a context (not copies). This is why we must use `asyncio.create_task` (which copies context) in tests, not `asyncio.gather` on bare coroutines. However, in production, each Django request is handled in its own task context by the ASGI handler — isolation is correct at the request boundary.
- `pytest-asyncio` version compatibility: ensure `asyncio_mode = "auto"` is set in `pyproject.toml` under `[tool.pytest.ini_options]` to avoid having to decorate every async test.
- After `clear_buffer()`, the `ContextVar` value is still the same list object (now empty). This is correct — the list is cleared, not replaced. The ContextVar still points to the same (now-empty) list.
